# Backend «Запары»

Начальный backend FastAPI, PostgreSQL и Alembic с недельным кэшем расписания и очередью. Авторизация, справочники и сохранение планов ещё не реализованы. Существующий frontend по-прежнему работает через свой прокси.

## Запуск в Docker

Команды выполняются из корня проекта. Скопируйте пример конфигурации и задайте свой пароль:

```bash
cp docker/backend.env.example docker/backend.env
```

Отредактируйте `docker/backend.env`: замените `ZAPARA_DB_PASSWORD`, при необходимости укажите имя базы и пользователя. Файл исключён из Git. Для локального сервера оставьте `ZAPARA_DB_HOST=postgres`.

Запустите локальный PostgreSQL и дождитесь готовности:

```bash
docker compose --env-file docker/backend.env -f docker/compose.backend.yaml --profile local-db up -d --wait postgres
```

Выполните миграции и запустите API:

```bash
docker compose --env-file docker/backend.env -f docker/compose.backend.yaml run --rm migrate
docker compose --env-file docker/backend.env -f docker/compose.backend.yaml up -d api
```

API доступен на `http://127.0.0.1:8000`, документация — `/docs`. `/health/live` показывает, что приложение отвечает; `/health/ready` дополнительно проверяет соединение с БД и соответствие текущей версии миграций. До применения миграций или при недоступной БД readiness отвечает `503`.

Остановка контейнеров без удаления данных:

```bash
docker compose --env-file docker/backend.env -f docker/compose.backend.yaml --profile local-db down
```

PostgreSQL хранит данные в отдельном Docker volume. Не используйте `down -v`, если данные нужно сохранить. При первом запуске PostgreSQL создаёт базу и пользователя из конфигурации; последующее изменение этих значений в файле не меняет уже созданные учётные данные или базу.

## Общий PostgreSQL

База `shared` может позже использоваться другими проектами. «Запара» хранит свои таблицы и `alembic_version` в схеме `zapara`, не затрагивая `public` и схемы других приложений. Каждая будущая миграция должна явно указывать схему `zapara`; автогенерацию нельзя запускать с удалением чужих объектов. Миграции создают историю Alembic и таблицы кэша в собственной схеме. Создание схемы выполняется при запуске Alembic до создания таблицы версий.

Для существующего сервера укажите `ZAPARA_DB_HOST`, порт, имя базы и учётную запись, доступную из контейнера API; сервис `postgres` в этом случае запускать не требуется. Учётной записи миграции нужны право подключения и право создать схему `zapara` либо доступ владельца к заранее созданной схеме. Если схема создана заранее, право `CREATE` на всю базу необязательно. Настройте отдельные роли и доступы для каждого проекта: схема сама по себе не ограничивает права пользователя PostgreSQL. Пример локального Compose использует начального пользователя PostgreSQL и предназначен для разработки; для общего сервера следует отдельно выдать минимально необходимые права и предусмотреть роль для миграций.

Миграции запускаются явно перед выпуском новой версии API, не выполняются автоматически каждым экземпляром приложения. Установка зависимостей и окружение приложения не создают и не удаляют базы или чужие схемы.

## Миграции

Внутри контейнера приложения команды Alembic запускаются из `/app`, например `alembic current` и `alembic upgrade head`. Для новой ревизии используйте `alembic revision -m "описание"` и явно указывайте `schema="zapara"` во всех операциях с таблицами. Ревизии хранятся в `backend/migrations/versions/`. Откат прикладных миграций нужно разрабатывать с учётом сохранности данных; базовая ревизия не удаляет схему.

## Кэш расписания

`GET /api/v1/schedule/{kind}/{external_id}?start=YYYY-MM-DD&finish=YYYY-MM-DD` принимает `person`, `group`, `auditorium`, `building` и числовой ID в пространстве соответствующей ручки ОмГТУ. Период ограничен 91 днём. Запрос разбивается на недельные окна; отсутствующие или устаревшие окна ставятся в очередь. Ответ содержит исходные записи, включая подгруппы, и состояние каждого окна (`fresh`, `stale`, `loading`, `unknown`). Пустой `events` при неполном покрытии не означает отсутствие занятий. Ручки пока не защищены авторизацией: порт Compose доступен только с локального компьютера.

Worker по умолчанию не запускается. После согласования допустимой частоты API задайте `ZAPARA_UPSTREAM_INTERVAL_SECONDS` в `docker/backend.env` (не менее 10 секунд) и запустите:

```bash
docker compose --env-file docker/backend.env -f docker/compose.backend.yaml --profile worker up -d worker
```

Общий лимит и блокировка действуют для всех worker, использующих одну БД. Запросы выполняются последовательно; ошибки и HTTP 429 задерживают повтор, `Retry-After` учитывается. Ответ с ошибкой, слишком большой или некорректный не заменяет последний успешный ответ. Запрошенные окна текущей и четырёх следующих недель обновляются после истечения 24 часов в течение 30 дней после последнего обращения. Справочник кафедры, предварительное создание окон всех её преподавателей и планирование остальных дат ещё не реализованы; полное ежедневное обновление кафедры пока не гарантируется.
